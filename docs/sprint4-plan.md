# План Спринта 4 — AI Meal Planner

## 1. Приоритизация задач

### Must-have (обязательно сделать)

- Завершить ключевые эндпоинты Backend API:
  - регистрация, авторизация, управление профилем;
  - создание и сохранение планов питания;
  - работа с пищевыми предпочтениями и аллергиями;
- Полная интеграция Backend API ↔ AI Engine (LLM):
  - отправка параметров пользователя (цель, бюджет, предпочтения),
  - получение и парсинг сгенерированных меню на 7 дней,
  - формирование структурированных данных (блюда, КБЖУ, рецепты).
- Хранение данных в SQLite:
  - пользователи, профили, цели,
  - планы питания, рецепты, ингредиенты,
  - история и избранное.
- Обновление документации:
  - OpenAPI/Swagger спецификация,
  - README по запуску и архитектуре.

### Should-have (желательно сделать)

- Реализация оффлайн-режима для мобильного приложения:
  - кэширование планов питания локально,
  - возможность просмотра без интернета.
- Интеграция с сервисами цен на продукты:
  - обновление стоимости ингредиентов,
  - оптимизация бюджета в реальном времени.
- Система фидбэка по рецептам:
  - оценка блюд,
  - адаптация будущих рекомендаций.
- Улучшение обработки ошибок API:
  - структурированные ответы,
  - информативные сообщения об ошибках.

### Could-have (если останется время)

- Генерация планов с учётом сезонности продуктов
- Интеграция с календарём для напоминаний о приёмах пищи
- Визуализация прогресса (графики питания, достижение целей)
- Совместное планирование для семейных аккаунтов
- Экспорт планов в PDF/календарь

---

## 2. Технический долг

- **Валидация AI-ответов** — отсутствует полноценная проверка корректности сгенерированных планов
- **Производительность генерации** — время отклика AI может превышать 30 секунд в пиковые нагрузки
- **Кэширование результатов** — отсутствует система кэширования повторяющихся запросов
- **Масштабируемость базы рецептов** — требуется оптимизация поиска и фильтрации
- **Обработка edge-cases** — не все пищевые комбинации корректно обрабатываются AI
- **Мобильная синхронизация** — не реализована надёжная синхронизация между устройствами

## 3. Планирование улучшений

- Внедрить Redis для кэширования часто запрашиваемых планов
- Оптимизировать промпты для LLM для более стабильной генерации
- Добавить систему валидации пищевой ценности (проверка баланса БЖУ)
- Реализовать фоновые задачи для асинхронной генерации сложных планов
- Добавить метрики качества генерации (соответствие целям, разнообразие, стоимость)
- Улучшить обработку аллергенов и пищевых ограничений
- Создать систему A/B тестирования разных алгоритмов генерации

## 5. Критерии успеха спринта

- ✅ Пользователь может создать полноценный план питания за ≤ 3 минуты
- ✅ AI генерирует корректные планы, соответствующие целям в ≥ 85% случаев
- ✅ Список покупок формируется автоматически для любого плана
- ✅ Мобильное приложение работает стабильно в онлайн/оффлайн режимах
- ✅ Среднее время генерации плана ≤ 25 секунд
- ✅ Система обрабатывает ≥ 95% пищевых ограничений корректно
- ✅ Документация позволяет новому разработчику запустить проект за 15 минут
