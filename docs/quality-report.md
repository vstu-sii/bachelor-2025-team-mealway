## 2. Quality Gates

**Quality Gates** — набор правил, через которые должно проходить каждое изменение в проекте.

### Текущее состояние

- ⚠️ **Базовые unit-тесты для API** (30% покрытие)
- ❌ **Интеграционные тесты AI-генерации**
- ❌ **End-to-end тесты мобильного приложения**
- ✅ **CI/CD пайплайн настроен** (GitHub Actions)
- ✅ **Проверка зависимостей безопасности** (dependabot)
- ⚠️ **Статический анализ кода** (flake8, mypy для Python; ktlint для Kotlin)
- ❌ **Анализ покрытия тестами**
- ✅ **Код-ревью обязательно для всех изменений**
- ✅ **Структурированная архитектура с чётким разделением слоёв**

### План улучшений

1. **Unit-тесты**
   - Генерация планов питания (80% покрытие сервисного слоя)
   - Расчёт КБЖУ и валидация пищевой ценности
   - Работа с пользовательскими предпочтениями и аллергиями

2. **Интеграционные тесты**
   - Полный цикл: параметры → AI → парсинг → список покупок
   - Интеграция с внешними API (LLM, продуктовые базы)
   - Тестирование оффлайн-синхронизации

3. **Мобильное E2E тестирование**
   - Сценарии создания и использования планов
   - Тестирование оффлайн-режима
   - UI-тесты основных экранов

4. **Покрытие тестами**
   - Цель: **≥ 75% бэкенд кода**, **≥ 60% мобильного приложения**

5. **Расширение CI/CD**
   - Автоматический запуск тестов при пулл-реквестах
   - Проверка производительности AI-генерации
   - Автодеплой на Staging после успешных тестов

6. **Security checks**
   - Регулярный аудит API ключей
   - Проверка JWT реализации
   - Анализ зависимостей на уязвимости

## 4. Security Audit (базовый аудит)

### Текущее состояние

- ✅ **Пароли хэшируются** (bcrypt для пользовательских паролей)
- ⚠️ **Rate limiting частично реализован** (только для основных эндпоинтов)
- ⚠️ **Мониторинг подозрительной активности** (базовое логирование)
- ⚠️ **Секреты хранятся в .env, шифрование для production**
- ✅ **CORS настроен корректно**
- ✅ **JWT с коротким временем жизни access-токенов**
- ✅ **HTTPS обязателен для production**
- ❌ **Нет регулярного аудита AI-промптов на безопасность**
- ❌ **Отсутствует валидация входных данных для AI-генерации**

### Основные риски

1. **Утечка API ключей LLM-сервисов** (высокая стоимость злоупотребления)
2. **Инъекции через пользовательские предпочтения** (передаются в LLM)
3. **Несанкционированный доступ к планам питания** (конфиденциальные данные о здоровье)
4. **DoS атаки на эндпоинты AI-генерации** (ресурсоёмкие запросы)

### План устранения рисков

1. **Усиление защиты API ключей:**
   - Ротация ключей каждые 30 дней
   - Ограничение по IP для production ключей
   - Мониторинг аномального использования

2. **Валидация и санитизация входных данных:**
   - Проверка пользовательского ввода перед передачей в LLM
   - Ограничение длины и формата параметров

3. **Улучшение контроля доступа:**
   - Детальная система разрешений для планов питания
   - Шифрование чувствительных данных в базе

4. **Защита от DoS:**
   - Строгий rate limiting для эндпоинтов генерации
   - Очередь запросов с приоритетами
   - Капча для подозрительной активности
