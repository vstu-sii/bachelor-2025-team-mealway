# MVP Scope — AI Meal Planner

## 1. Определение MVP

В состав MVP входят основные пользовательские сценарии (UC1–UC12), необходимые для функционирования сервиса:


1. **Выбор продуктов:** Настройка аллергий, запрещённых и любимых продуктов.
2. **Генерация меню:** AI создаёт персонализированный недельный план питания с рецептами и автоматически формирует список покупок по категориям.
3. **Регистрация:** Создание аккаунта с email и паролем.
4. **Авторизация:** Вход в систему с помощью учётных данных.
5. **Сохранение планов:** Сохранение готового плана в аккаунте.
6. **Просмотр планов:** Доступ к списку всех сохранённых планов и их детальному просмотру.
7. **Заполнение профиля:** Указание роста, веса, возраста, активности и цели (похудение/набор/здоровье).

**Итог:**  
Все ключевые use-cases UC1-UC7 реализованы.  
Сквозной сценарий работает:  
*пользователь → настройка профиля → AI-генерация → план питания → список покупок → сохранение.*

## 2. Приоритизация backlog

Так как MVP завершён, текущий backlog состоит из задач по улучшению качества, безопасности, масштабированию и расширению функциональности.

### Основные направления:

- **Качество AI-генерации**
  - Механизм пользовательского фидбэка для улучшения рекомендаций
  - A/B тестирование разных версий AI-пайплайна

- **Производительность и масштабируемость**
  - Кэширование часто запрашиваемых планов в Redis
  - Оптимизация времени генерации AI-планов
  - Поддержка большего количества одновременных пользователей

- **Расширение функциональности**
  - Интеграция с сервисами доставки продуктов
  - Поддержка семейных аккаунтов и совместного планирования
  - Генерация планов с учётом сезонности продуктов
  - Расширенная аналитика прогресса (графики, отчёты)

- **UX/UI улучшения**
  - Адаптация интерфейса под различные размеры экранов
  - Улучшение навигации по недельному плану
  - Визуализация пищевой ценности (диаграммы, графики)
  - Персонализированные советы по питанию

## 3. Планирование следующего спринта

Так как текущий спринт завершает MVP, в следующем спринте планируются улучшения, закрывающие риски выхода в продакшен и повышающие качество сервиса.

### Задачи следующего спринта:

1. **Оптимизация производительности:**
   - Внедрение Redis для кэширования сгенерированных планов
   - Оптимизация промптов для уменьшения времени генерации на 30%

2. **Улучшение качества AI-генерации:**
   - Реализация системы валидации сгенерированных планов
   - Добавление механизма пользовательского фидбэка по рецептам

3. **Расширение тестового покрытия:**
   - Увеличение покрытия unit-тестами до 60%
   - Добавление интеграционных тестов для полного цикла генерации
   - Нагрузочное тестирование API

4. **Мониторинг и аналитика:**
   - Внедрение метрик качества AI-генерации
   - Настройка алертов для критических сбоев
   - Аналитика пользовательского поведения

## 4. Управление техническим долгом

На текущий момент выявлены следующие критичные зоны технического долга:

- **Ограниченное тестовое покрытие** — повышает риск регрессий в AI-генерации
- **Отсутствие полноценной системы мониторинга** — сложно отслеживать качество AI-рекомендаций
- **Неоптимальная производительность генерации** — при пиковой нагрузке время отклика превышает целевые 25 секунд

### План погашения технического долга:
1. **Спринт 1:** Увеличение тестового покрытия до 60%
2. **Спринт 2:** Внедрение системы мониторинга качества AI
3. **Спринт 3:** Оптимизация производительности генерации
4. **Спринт 5:** Усиление валидации и безопасности AI-пайплайна

## 5. Критерии готовности к production

Для перехода к продакшен-версии необходимо достичь следующих показателей:

### Технические критерии:
- ✅ Время генерации плана: ≤ 25 секунд в 95% случаев
- ✅ Доступность API: ≥ 99.5%
- ✅ Тестовое покрытие: ≥ 75% критического функционала
- ✅ Процент успешных генераций: ≥ 90%

### Качественные критерии:
- ✅ Соответствие планов целям пользователя: ≥ 85%
- ✅ Учёт пищевых ограничений: ≥ 99%
