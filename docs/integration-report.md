# Контроль интеграции — AI Meal Planner

## 1. Введение

Цель данного отчёта — зафиксировать текущее состояние интеграции компонентов прототипа **AI Meal Planner**, провести end-to-end анализ всей системы и выявить проблемные зоны, требующие доработки перед Demo Day.

Система включает следующие подсистемы:

- **Frontend Mobile** (Android + Kotlin)
- **Backend API** (FastAPI + Python)
- **SQLite** (основное хранилище пользователей и планов)
- **LLM API** (transformers)
---

## 2. End-to-end тестирование прототипа

### Целевой сценарий (MVP)

1. Пользователь регистрируется и заполняет профиль.
2. Проходит пошаговую форму: выбирает цель → указывает предпочтения → задаёт бюджет.
4. Backend API принимает запрос и передаёт данные в LLM Engine.
5. LLM Engine:
   - анализирует параметры пользователя,
   - генерирует персонализированное меню на 7 дней,
   - рассчитывает КБЖУ для каждого приёма пищи,
   - генерирует рецепты.
6. Модуль списка покупок:
   - анализирует все рецепты плана,
   - генерирует оптимизированный список ингредиентов,
7. Backend сохраняет план в базе данных и кэширует в Redis.
8. Пользователю отображается готовый план с навигацией по дням.
9. Пользователь может сохранить план или сгенерировать заново.

### Фактическое состояние

- Регистрация и авторизация — реализованы полностью.
- Форма ввода параметров пользователя — готова.
- API работы с планами питания — основная логика готова.
- Интеграция с LLM API — работает, но требует оптимизации промптов.
- Генерация списка покупок — реализована, но без интеграции с актуальными ценами.
- SQLite — основные таблицы созданы.
- Redis — подключён, кэширование работает частично.
- Мобильное приложение — базовые экраны готовы, интеграция с бэкендом частичная.
- Полный end-to-end сценарий — **не завершён**, отсутствует связка: параметры → LLM → парсинг → список покупок → мобильное отображение.

## 4. Найденные проблемы

1. **Отсутствует завершённый end-to-end пайплайн** от ввода параметров до получения готового плана в мобильном приложении.
2. **Нестабильность LLM-генерации** — качество меню варьируется, требуются улучшенные промпты и валидация.
3. **Список покупок не учитывает актуальные цены** — расчёт стоимости основан на средних значениях.
4. **Мобильное приложение работает частично оффлайн** — кэширование планов реализовано не полностью.
5. **Отсутствует синхронизация между устройствами** — пользователь не может продолжить работу с другого устройства.
6. **Не реализована система фидбэка** — невозможно оценивать рецепты для улучшения рекомендаций.
7. **Проблемы с производительностью** — генерация сложных планов может занимать до 40 секунд.
8. **Недостаточное покрытие интеграционными тестами** — многие сценарии не тестируются автоматически.

- Добавить систему ретраев и фоновой обработки для долгих генераций.

### **Мобильное приложение**

- Настроить мониторинг производительности API и LLM-вызовов.
- Реализовать систему логов для отладки генерации.

### **Тестирование и качество**

- Реализовать нагрузочное тестирование API.

### **Документация**

  2. Улучшить качество и скорость генерации меню.
  3. Обеспечить стабильную работу мобильного приложения.
  4. Подготовить систему к демонстрации на Demo Day.

**Риски:** Время генерации меню может превышать допустимые для UX лимиты, качество AI-рекомендаций может быть недостаточно стабильным для production-использования.
